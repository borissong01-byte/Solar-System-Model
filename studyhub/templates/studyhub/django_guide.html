How Django fits together

Django is the Python toolkit powering the Study Hub pages. Follow the path from a browser address to the page you see, then explore the files that make each step happen.

When someone opens a page

1. URL — the address

A URL is the page address. config/urls.py is the project’s main map; it points the Study Hub section to the app. studyhub/urls.py maps app addresses such as /science/ to views.

2. View — the page handler

studyhub/views.py contains Python functions that respond to a URL. A view can choose a template or return a file, like the solar system model.

3. Template — the page layout

Templates are HTML files with optional Django tags. CSS inside them controls appearance; JavaScript can add browser interactions.

4. Browser — what you see

Django sends the finished page to your browser. HTML describes content, CSS styles it, and JavaScript can make it interactive.

Project files and data

manage.py

A command helper for starting the local server and running Django commands.

config/settings.py

Project-wide choices: apps, database location, language, time zone, and allowed website hosts.

models.py

Describes data an app stores, such as lessons or quiz questions. Django can use models to create database tables. This app does not need one yet.

Database and migrations

A database stores information for later. The app’s migrations/ folder records steps for updating database tables when models change. No app migration is needed yet.

__init__.py

An often-empty file marking a folder as a Python package, so code in it can be imported.

API

An API lets software systems exchange requests and information. This learning site does not currently use one.

Quick way to remember: URL finds the view, the view picks a template, and Django sends the result to your browser.
